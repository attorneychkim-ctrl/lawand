## 2026-08-20 — 후기 요청 템플릿 저장 실패 피드백 운영 진단

- 신고된 두 직원의 후기 요청 템플릿을 본문 원문 없이 운영 DB 메타데이터로 대조했다. 두
  템플릿 모두 당일 `2026-08-20 15:44:24`·`16:05:11 KST`에 실제 UPDATE가 성공했고 현재
  저장값은 링크 변수와 500바이트 제한을 만족한다. 뒤쪽 저장값은 센트릭스 기준 468/500
  바이트로 여유가 작다.
- gateway·ERP application journal, 같은 시간대 Caddy의 해당 경로 오류와 RDS PostgreSQL
  error log를 확인했으나 후기 요청 템플릿 관련 5xx·DB constraint·중복 오류는 없었다. 두 앱은
  active, container restart 0이고 CloudWatch ALARM도 0이다.
- 원인은 서버 저장 장애가 아니라 클라이언트의 무응답형 검증 UX로 좁혔다. 편집 본문이
  500바이트를 넘거나 `{{후기작성링크}}`를 지우거나 허용되지 않은 변수를 넣으면 저장 버튼을
  비활성화하고 `saveTemplate`이 fetch 전에 반환한다. 비활성 기본 버튼은 `cursor: wait`를 써서
  사용자는 저장 처리 중 또는 저장 실패로 오인할 수 있고, 서버 요청이 없어 운영 로그에도
  남지 않는다. 정확한 실패 초안과 검증 사유는 현재 보존하지 않으므로 두 신고 각각이 어느
  조건을 위반했는지는 사후 확정할 수 없다.
- 이번 세션은 진단만 수행했다. 애플리케이션 코드·DB·운영 데이터·배포·외부 발송은 변경하지
  않았다. `HERDR_ENV`가 비어 있고 HERDR 서버도 실행 중이 아니어서 관리 워크트리 목록은
  확인할 수 없었다.

## 2026-08-20 — Orca 운영 기준 교정·후기 템플릿 저장 지연 재진단

- 사용자가 현재 작업 관리자가 Orca이고 HERDR가 아니라고 교정했다. `orca-ide status --json`의
  runtime ready/reachable과 앱 `1.4.185`, `orca-ide worktree current --json`의
  `LegalFlow/review_save_error`·base `origin/main`·`in-progress` 상태를 확인했다. 이에 따라
  `AGENTS.md`와 `CURRENT.md`의 현재 기준을 Orca로 바꾸고 컨텍스트 검사에 필수 문구와 HERDR
  회귀 방지 규칙을 추가했다. 위 과거 항목의 HERDR 상태와 이후 진단 결론은 이 항목으로
  정정한다.
- 공서아의 정확한 피드백은 저장 버튼 비활성화가 아니라 “이전 발송 내용이 남은 채 로딩이
  계속됨”이었다. 운영 DB에는 공서아·김지안 템플릿 UPDATE가 각각 `15:44:24`·`16:05:11 KST`에
  최종 반영됐지만, 같은 구간 gateway request DB pool은 max 20을 모두 사용한 채 대기했다.
  분 단위 waiting maximum은 공서아 반영 분 3, 바로 다음 분 11, 김지안 직전 분 17, 반영 분
  1이었고 주변 구간 최고 97까지 반복됐다. 같은 구간 RDS CPU는 대체로 낮아 DB CPU 포화나
  constraint 오류 정황은 없다.
- 따라서 일차 원인은 순간적인 gateway request pool 적체와, 저장 응답이 지연·유실될 때
  브라우저가 timeout 후 서버 값을 재조회해 성공 여부를 조정하지 않는 UI/관측 공백으로
  좁혔다. DB에는 성공했는데 화면은 이전 값·로딩 상태로 남았다는 현상과 일치한다. 경로별
  성공·소요 시간 로그와 실패 초안이 없어 두 사용자의 각 클릭을 사후 확정할 수는 없다.
  500바이트·필수 변수 검증이 설명 없이 버튼을 비활성화하고 wait cursor를 보이는 문제는
  별도의 2차 UX 결함으로 유지한다.
- 이 교정에서는 문서·검사 기준만 변경했다. 애플리케이션 코드·DB·운영 데이터·배포·외부
  발송은 변경하지 않았다. 후속 작업은 저장 timeout·서버 결과 재조회/동기화·명시적 오류와
  개인정보 없는 route duration/status 로그를 추가하고, pool 크기 변경 전에 점유 요청을
  식별하는 것이다.

## 2026-08-20 — 후기 요청 비활성 버튼 가짜 로딩 커서 수정

- 사용자가 실제 상태를 재확인했다. 템플릿 저장은 정상 완료됐고 수정 초안이 없어
  `변경사항 저장` 버튼이 비활성인 상태였으며, 수신 고객을 선택하지 않은
  `0명에게 후기 요청` 버튼도 같은 대기 커서를 보였다. 두 버튼 모두 공통
  `.primary-button:disabled { cursor: wait; }`를 적용받은 것이 직접 원인이었다. 따라서 위
  항목의 gateway request pool 적체를 이번 신고의 일차 원인으로 본 결론과 timeout·재동기화
  후속 범위는 취소한다. 당시 pool waiting은 별도로 관측된 운영 정황일 뿐 이 UI 신고와의
  인과는 확인되지 않았다.
- 템플릿 저장 버튼에는 `aria-busy={templateBusy}`, 후기 요청 버튼에는
  `aria-busy={sending}`을 추가했다. 후기 화면의 두 버튼은 비동기 작업 중이 아닌 비활성
  상태에서 `cursor: not-allowed`를 사용하고, 실제 저장·발송 중에는 기존 대기 커서를
  유지한다. 저장 API·발송 조건·데이터 흐름은 변경하지 않았다.
- ERP lint·typecheck·의존 패키지 포함 production build와 `git diff --check`를 통과했다.
  DB·migration·운영 데이터·외부 발송·`main`·운영 배포는 변경하지 않았다. 운영 반영은
  `LegalFlow/review_save_error`를 메인 세션에서 통합·배포한 뒤 완료로 간주한다.
