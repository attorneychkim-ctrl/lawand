# ERP 직원 인증·권한·감사 v1

> 상태: 2026-07-30 소속·지역·회사 지정 프로필과 리걸프렌즈 계정 매핑 관리까지 구현
> 범위: 초대 전용 가입, 로그인·로그아웃, 서버 세션, 역할, 상담 PII 조회 감사,
> 직원별 리걸프렌즈 로그인 ID·member_idx 관리
> 제외: 이메일 초대 발송, 비밀번호 재설정, MFA, 계정 비활성화 UI, 세부 상담 권한

## 1. 경계

- 공개 회원가입은 제공하지 않는다.
- 최초 관리자는 운영자가 이름·소속·지역·부서·직책을 포함한 CLI 명령으로 72시간
  유효한 1회용 초대를 만든다.
- 이후에는 `admin` 역할 직원만 ERP `/staff`에서 초대 링크를 만들 수 있다.
- 초대받은 직원은 회사가 지정한 이메일·이름·소속·지역·부서·직책·역할을 수정할 수
  없으며 비밀번호만 설정한다. gateway는 가입 시 브라우저 값이 아니라 초대 원장을
  다시 읽어 프로필과 멤버십을 만든다.
- 브라우저는 HttpOnly·SameSite=Strict 쿠키만 보관한다. ERP의 API Key와 DB 접속정보는
  브라우저에 전달하지 않는다.
- ERP 서버가 gateway를 호출할 때 내부 API 키와 직원 세션 토큰을 함께 전달한다.
  상담 목록·상세 API는 둘 중 하나라도 없거나 유효하지 않으면 거부한다.

## 2. 데이터 분리

| 테이블 | 책임 |
|---|---|
| `staff_users` | 정규화 이메일, scrypt 비밀번호 해시, 활성 상태, 로그인 실패·잠금 |
| `staff_profiles` | 회사가 지정한 직원 이름 |
| `staff_organizations` | 소속 기준값: 법무법인 로앤, 리걸플로 |
| `staff_regions` | 근무 지역 기준값: 서울, 대전, 부산 |
| `staff_memberships` | 계정별 소속·지역·부서·직책·역할과 주 멤버십 |
| `staff_invitations` | 회사 지정 직원정보, 초대 토큰 SHA-256 지문, 만료·사용·취소 |
| `staff_sessions` | 세션 토큰 SHA-256 지문, 12시간 만료·폐기 |
| `staff_audit_logs` | 로그인·로그아웃·초대·상담 목록/PII 상세 조회 기록 |
| `staff_external_accounts` | 직원별 외부 서비스 ID의 활성 매핑과 변경 이력 |

비밀번호와 초대·세션 토큰 원문은 DB에 저장하지 않는다. 비밀번호는 Node `scrypt`
`N=32768, r=8, p=1`로 16바이트 난수 salt와 함께 해시한다. 초대·세션 토큰은
32바이트 CSPRNG 원문을 한 번 발급하고 SHA-256 지문만 저장한다.

한 직원이 여러 소속이나 지역을 겸할 수 있도록 계정과 멤버십은 1:N이다. 초대 가입은
첫 주 멤버십 하나를 만들며 추가 멤버십은 향후 관리자 직원 편집 화면에서만 부여한다.

## 3. 현재 역할·권한 그룹

- `admin`: 관리자
- `full_time`: 정규직
- `part_time`: 아르바이트
- `separate_accounting`: 별산
- `civil_complaint_vendor`: 민원업체

현재는 모든 역할이 상담 목록·상세를 조회할 수 있고 `admin`만 직원 초대를 만든다.
`admin`은 초대 시 리걸프렌즈 로그인 ID와 숫자형 `member_idx`를 함께 선택 입력하고
`/staff`에서 직원별 두 값을 함께 연결·변경·해제할 수 있다. 같은 활성 로그인 ID나
`member_idx`를 두 직원에게 중복 연결할 수 없으며 변경은
`staff.external_account.updated` 감사로그에 남는다. 로그인 ID는 추후 담당자 변경에,
`member_idx`는 V2 신건 최초 담당자 지정에 사용한다.
`상담하기`, 담당 배정, 상태 변경, 메모·메신저를 구현할 때 역할 프리셋과 소속·지역·
담당 범위를 결합한 모듈 단위 보기·처리·관리 권한으로 좁힌다. 직원별 페이지 권한을
일일이 설정하는 방식은 사용하지 않는다.

## 4. 운영 규칙

- 로그인 5회 실패 시 계정을 15분 잠근다.
- 세션은 발급 후 12시간 뒤 만료되며 로그아웃 시 서버에서 즉시 폐기한다.
- 초대는 72시간 뒤 만료되고 한 번 수락하면 재사용할 수 없다.
- 같은 이메일의 새 초대를 만들면 사용 전 기존 초대는 취소한다.
- 퇴사자는 계정을 삭제하지 않고 `disabled`로 바꿔 과거 담당·감사 참조를 보존한다.
- 상담 목록 조회는 `consultation.list.viewed`, 상세 PII 조회는
  `consultation.pii.viewed`로 남긴다.

## 5. 최초 관리자

실제 관리자 이메일을 정한 뒤 gateway 디렉터리의 로컬/운영 환경변수를 준비하고 실행한다.

```bash
corepack pnpm --filter @lawand/gateway staff:bootstrap \
  admin@example.com "관리자 이름" lawand seoul "경영지원" "대표"
```

직원 계정이 한 명이라도 생성된 뒤에는 bootstrap 명령이 거부된다. 출력되는 초대 URL은
비밀값으로 취급해 대상자에게 안전한 채널로 한 번만 전달한다.

## 6. 외부 배포 전 남은 게이트

- 실제 관리자 초대와 계정 복구 담당자 지정
- 비밀번호 재설정·초대 재발급·계정 비활성화 UI
- MFA 또는 사내 SSO 도입
- reverse proxy 로그인 rate limit과 보안 모니터링
- 운영 HTTPS·비밀관리·쿠키 도메인·ERP base URL 검증
- 역할별 상담 목록 범위와 `상담하기`·담당 변경 명령 권한 확정
