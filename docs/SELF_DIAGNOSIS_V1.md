# 로앤 자가진단·유사사건 비교 v1

## 1. 상태와 목적

`/bank/self-diagnosis`는 고객이 입력한 거주지역·소득·가족·법원·채무·재산 조건을 로앤이
진행한 사건과 비교해 유사사건 다섯 건의 변제금·변제개월·예상 지출·추가생계비·
총변제금·변제율·주요 절차일을 보여주고, 같은 입력과 연락정보를 ERP 상담으로 접수하는
로컬 구현이다.

기술 구현과 로컬 데이터 검증은 완료했지만 운영 공개 승인을 뜻하지 않는다. 개별 과거
사건에서 파생된 다차원 조합은 이름·전화·사건번호가 없어도 재식별 가능성이 남으므로,
운영 배포 전 책임 변호사의 법률·광고 문구 검토와 개인정보 처리 근거·사례 이용 범위,
희소 조합의 집계 또는 추가 일반화 기준을 확정해야 한다.

## 2. 원천과 런타임 경계

- 원천은 로컬 PostgreSQL `lawand_dev`의 `CB.TblCBCase` 중 `Office_idx=56`이고,
  홈페이지와 gateway 런타임 역할은 이 테이블에 접근하지 않는다.
- 동기화 스크립트는 이름·전화·사건번호·원본 사건 식별자를 SELECT하지 않는다.
- 런타임은 `public.self_diagnosis_case_profiles`만 조회한다. 새 UUID는 동기화 때
  임의로 만들며 원본 행과 연결할 수 있는 키를 저장하지 않는다.
- 고객이 사건 진행 순서를 바로 이해할 수 있도록 신청서 접수·금지·개시·인가·파산선고·
  면책허가의 원본 날짜를 읽기 모델과 응답에 포함한다. 날짜는 다른 조건과 결합될 때
  재식별 단서가 될 수 있으므로 운영 공개 전 최소 집단 크기·일반화 여부를 별도로
  승인해야 한다.
- 금액은 원 단위 정수로 정규화하고 고객 화면에서는 읽기 쉽도록 만원 단위로 반올림한다.
- 회생사건은 `estimated_spend`, `living_cost_type`, `living_cost_cost`, `total_payment`,
  `repayment_rate`를 읽기 모델에 포함한다. 원천 필드를 별도로 재계산하거나 보정하지 않고
  고객 화면에서 예상 지출·추가생계비 유형과 금액·총변제금·변제율로 구분해 표시한다.
- 2026-08-03 현재 `Office_idx=56`, `case_type IN (1,2)` 원천 1,773건 중 실제
  신청서 접수일과 필수 변제·결정일 기록을 갖춘 1,759건이 읽기 모델에 있다.
  개인회생 1,342건, 개인파산·면책 417건이다.

재구축은 다음 명령으로 수행한다. 기존 읽기 모델을 교체하는 작업이므로 원천 행 수와
결과 분포를 먼저 확인한다.

```bash
corepack pnpm diagnosis:sync -- --replace
```

## 3. 고객 입력

필수 입력은 다음과 같다.

- 현재 거주 중인 시·도, 거주지역으로 안내·선택한 관할법원, 월평균 소득, 소득형태
- 담보 없는 채무, 담보부 채무, 예상 청산가치, 조세 등 우선권채권 여부
- 혼인상태, 미성년 자녀 수, 거주형태
- 이름, 휴대전화, 개인정보 수집·이용 동의

금액 입력은 원 단위를 사용하고 입력칸 아래에 현재 값의 읽기 쉬운 만원·억원 표현을
함께 표시한다. 월평균 소득·담보 없는 채무·담보부 채무·예상 청산가치에 `0원`이 아닌
10만원 미만 값을 입력하고 다음 단계로 이동하면, 고객에게 입력한 원 금액과
`입력값 × 10,000`의 만원 단위 해석을 함께 보여 준다. 고객은 만원 단위로 수정하거나,
원 단위를 그대로 확정하거나, 값을 다시 입력해야 한다. 변환 후보가 필드 허용 상한을
넘으면 변환 버튼 없이 원 단위 확정과 재입력만 제공한다. 제출 계약은 원 단위를 그대로
확정한 의심 필드명을 함께 받아, 확인되지 않은 저액이 UI 우회로 접수되는 것을 거부한다.

코드 표시는 고객 화면과 ERP에서 다음 명칭으로 변환한다.

| 항목 | 코드와 명칭 |
|---|---|
| 소득형태 | 1 급여소득 · 2 사업소득 · 3 급여+사업소득 · 4 연금소득 · 5 생계급여 · 6 급여변동 · 100 기타 |
| 거주형태 | 1 자가 · 2 사택·기숙사 · 3 임차(전·월세) · 4 친족 소유 무상거주 · 5 친족 외 소유 무상거주 · 100 기타 |
| 혼인상태 | 1 기혼 · 2 미혼 · 3 이혼 |
| 추가생계비 | 0 추가 인정 없음 · 1 생계비 · 2 주거비 · 3 의료비 · 4 교육비 · 5 식비 · 6 전기·가스·수도료 · 7 교통비·차량유지비 · 8 의복비 · 9 통신비 · 100 기타 |

관할법원은 고객에게 전체 법원 목록을 바로 묻지 않는다. 상담 요청과 같은 국내 17개
시·도 선택을 먼저 받고, 단일 관할은 바로 표시하며 도 단위만으로 하나를 정할 수 없거나
법률상 추가 관할이 있는 지역만 고객이 선택한다.

| 거주지역 | 자가진단에 표시하는 법원 |
|---|---|
| 서울 | 서울회생법원 |
| 부산 | 부산회생법원 |
| 대구·경북 | 대구회생법원 |
| 인천 | 인천지방법원 |
| 광주·전남 | 광주회생법원 |
| 대전·세종·충남 | 대전회생법원 |
| 경기 | 수원회생법원, 의정부지방법원, 부천·김포의 인천지방법원 중 선택 |
| 강원 | 춘천지방법원, 법 제3조제10항의 강릉지원, 철원의 의정부지방법원 중 선택 |
| 충북 | 청주지방법원 또는 법 제3조제12항의 대전회생법원 |
| 울산 | 울산지방법원 또는 법 제3조제11항의 부산회생법원 |
| 경남 | 창원지방법원 또는 법 제3조제11항의 부산회생법원 |
| 전북 | 전주지방법원 또는 법 제3조제13항의 광주회생법원 |
| 제주 | 제주지방법원 또는 법 제3조제13항의 광주회생법원 |

이 표시는 거주지역 기준 1차 안내다. 법 제3조에 따라 보통재판적뿐 아니라 계속 근무하는
사무소·영업소, 재산 소재, 배우자 등 관련 사건이 관할에 영향을 줄 수 있으므로 실제
제출 법원을 확정하는 문구로 사용하지 않는다. 서버는 제출된 거주지역과 위 허용 법원의
조합을 다시 검증하며, 해외·기타는 거주지역만으로 국내 관할을 안내할 수 없어 자가진단
v1 선택지에서 제외한다.

`debt_reasons`는 원천 문서의 정의와 실제 데이터가 다를 수 있어 v1 입력·매칭·결과에서
제외한다. `living_cost_type`은 고객 입력이나 유사도 가중치에는 사용하지 않고, 선택된
원천 사건에서 실제 추가생계비가 어떻게 기록됐는지 설명하는 결과 필드로만 사용한다.

## 4. 판단 제약과 유사도

모델 버전은 `office-56-v3`이다. 결과는 법률 판단이나 인가·면책 보장이 아니라 상담 전
비교자료다.

1. 최소 필요 총변제액은 `max(청산가치, 담보 없는 채무 × 3%)`로 둔다.
2. 2026년 기준 중위소득 60%를 생계비 참고값으로 사용한다. 본인을 포함한 가구원 수를
   1~6명 범위에서 적용한다.
3. 고객에게 부양가족 수를 별도로 단정하게 하지 않고 미성년 자녀 수를 최초 비교값으로
   사용한다. 이 값으로 계산한 가용소득이 60개월 안에 최소 필요 총변제액을 충족하지
   못하면 인정 가정 인원을 한 명씩 줄인 비교 시나리오를 계산한다. 이는 실제 부양가족
   인정 결과가 아니라 상담에서 소명 필요성을 확인하기 위한 표시다.
4. 1인 참고 생계비 이하 소득이거나 부양가족을 0명까지 줄인 60개월 시나리오로도
   제약을 충족하지 못하면 `개인파산·면책 검토` 방향으로 분기한다. 유사한 회생사건이
   단순히 부족하다는 이유만으로 파산 방향을 제시하지 않는다.
5. 개인회생 후보는 우선권채권 여부가 입력과 정확히 같고, 1~60개월, 원천 변제율 3%
   이상, 원천 총변제금이 원천 청산가치와 고객의 최소 필요 총변제액 이상인 사건만
   남긴다.
6. 남은 후보 중 미성년 자녀 수가 같은 사건을 먼저 확보한다. 그 안에서 월소득이 정확히
   같거나 5%·10만원 이내로 가까운 사건이 다섯 건 이상이면 그 집단만 비교하고, 부족할
   때만 같은 자녀 수 전체로 넓힌다. 이 계층을 통과한 후보는 월소득에 가장 큰 연속형
   가중치를 두고 법원, 소득형태, 혼인상태, 원천 인정 부양가족 수, 총채무, 청산가치를
   함께 계산한다. 거주형태는 보조 가중치로 사용한다. 같은 자녀 수 사건조차 다섯 건
   미만인 희소 입력에서만 전체 후보로 완화한다.
7. 파산·면책 후보는 총채무와 청산가치, 법원, 혼인상태, 미성년 자녀를 비교하고
   파산선고일 기록이 있는 사건만 사용한다. 현재 원천 파산사건 상당수는 소득이
   0으로 저장돼 있으므로 결과 화면에 0원으로 단정하지 않고 `원천 기록 없음`으로
   표시한다.
8. 회생 결과 카드는 원천 월소득을 예상 지출금액과 월 변제금으로 나눈 배분 막대를
   표시한다. 총변제금·변제율과 추가생계비 유형·금액은 별도 수치로 보여주며, 각 결정일
   옆의 경과일은 신청서 접수일과 해당 결정일의 날짜 차이로 계산한다.

책임 변호사 검토 전에는 위 3% 기준이나 생계비 참고값을 법원의 확정 산식처럼 표현하지
않는다. 법률상 개인회생 변제기간은 원칙적으로 3년을 넘지 않고 특별한 사정에서 5년
범위가 가능하며, 생계비와 부양가족 인정은 사건별 자료와 법원 판단에 따라 달라진다.

## 5. API·ERP 흐름

1. 브라우저는 `POST /api/self-diagnoses`를 same-origin으로 호출한다.
2. 홈페이지 서버는 공개 접수 전용 키와 비식별 네트워크 키를 붙여 gateway의
   `POST /v1/self-diagnoses`로 전달한다.
3. gateway는 비식별 읽기 모델에서 다섯 건을 선별한 뒤 일반 상담 접수 트랜잭션을
   `mode=self_diagnosis`로 실행한다.
4. 이름·전화·전체 입력·서버 판정은 기존 AES-GCM 상담 intake에 암호화해 저장하고,
   고객 결과 화면에 표시한 유사사례 카드 다섯 건의 순서·비교값·주요 절차일도 함께
   저장한다. 원본 사건 식별자·사건번호·이름·전화번호는 카드 스냅샷에 포함하지 않으며,
   광고 귀속에는 복제하지 않는다. 보관기간은 상담 접수일부터 1년이다.
5. ERP 목록과 상세에는 `자가진단` 접수 방식, 입력 코드의 한글 명칭, 비교 방향과
   제약값을 표시하고, 상담자가 의뢰인이 실제로 본 다섯 카드의 순서·금액·절차일을
   요청별로 확인할 수 있게 한다. 이전 접수처럼 카드 스냅샷이 없는 원장은 별도로
   표시한다.
6. 고객 응답에는 원본 식별자는 넣지 않지만 변제계획 이해를 위한 예상 지출·추가생계비·
   총변제금·변제율과 진행 순서 확인을 위한 주요 절차일은 넣는다. 비교사건이 정확히
   다섯 건이 아니면 임의로 파산사건을 섞지 않고 서비스 불가 응답을 반환한다.
