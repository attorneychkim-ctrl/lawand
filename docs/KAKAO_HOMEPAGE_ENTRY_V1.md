# 홈페이지 카카오 1:1 상담 진입 v1

## 목적

홈페이지의 카카오 상담 버튼을 누른 고객에게 이름 또는 카카오톡 표시명을 먼저 받아
ERP에 자동으로 남긴다. 상담원은 도착 시각을 추정하지 않고 입력 이름으로 채팅을 찾아
바로 `상담하기`를 누른다. 채팅방 진입이나 메시지 전송 성공을 알 수 없는 카카오 일반
채널 링크의 제약은 대기·확정·무효 상태로 다룬다. 직접 채널을 방문한 소수 고객은
기존처럼 수동 등록한다.

## 고객 흐름

1. 고객이 홈페이지의 카카오 CTA를 누른다.
2. client-only 모달에서 `이름 또는 카카오톡 표시명`을 필수로 입력한다.
3. 고객이 `확인하고 카카오톡 열기`를 누르면 브라우저가 same-origin
   `POST /api/kakao-entry`를 새 탭으로 제출한다.
4. 홈페이지 서버가 gateway `POST /v1/kakao/homepage-entries`에 이름이 포함된 대기
   접수를 만든다.
5. 홈페이지 서버가 `https://pf.kakao.com/_AeGxoxl/chat`으로 303 이동시킨다.

빈 문자열과 공백뿐인 값은 확인 버튼을 활성화하지 않으며, 조작된 요청도 홈페이지와
gateway 스키마가 모두 400으로 거부한다. 이 경우 ERP 접수와 카카오 이동은 모두 일어나지
않는다.

gateway 저장이 일시적으로 실패해도 카카오 이동은 계속한다. 실패 로그에는 원인 분류와
HTTP 상태만 남기고 고객 식별정보는 남기지 않는다.

## 중복 클릭

브라우저 탭의 `sessionStorage` v2 키에 UUID와 생성 시각을 저장하고 30분 동안 재사용한다.
같은 키가 다시 오면 상담과 요청을 추가하지 않고 `kakao_homepage_entries.click_count`,
`last_clicked_at`만 갱신한다. 30분이 지난 뒤의 새 행동은 새 접수로 본다.

## 데이터와 상태

- 접수 source: `homepage_kakao`
- 채널: `kakao_channel`
- 초기 상태: `pending` (`고객 이름 입력 완료·메시지 확인 대기`)
- ERP 이름: `<고객 입력 이름>_<접수번호 뒤 8자리>_플친`
- 요청 이름: 고객이 입력한 이름 또는 표시명을 별도 AES-256-GCM 암호화
- DB 전화번호: `NULL`
- ERP 전화 표시: `010-0000-0000 · 미수집`
- 개인정보 처리 근거: `customer_initiated_channel_entry`
- 고객 발화 원문·카카오 사용자 키·가짜 전화번호: 저장하지 않음

일반 채널 링크는 고객의 카카오 식별자와 실제 채팅방 표시명을 서버에 주지 않는다.
따라서 고객 입력 이름은 채팅방을 찾는 검색 단서이지 카카오가 보증한 식별자가 아니다.
접수번호 뒤 8자리는 동명이인과 반복 접수를 내부에서 구분한다.

## 직원 운영

### 채팅 확인

ERP 목록은 고객이 입력한 이름과 `카톡 이름 입력` 배지를 즉시 표시하고 신규 상태의
`상담하기`를 허용한다. 직원이 카카오 채널 관리자에서 같은 이름의 새 메시지를 찾고
`상담하기`를 누르면 같은 DB 트랜잭션에서 entry를 `confirmed`로 바꾸고 해당 직원을
담당자로 배정한다. 즉 표시명 재입력과 별도 확인 버튼을 거치지 않는다.

고객 오입력이나 실제 채팅방 표시명이 다른 경우에는 상세 화면에서 이름을 고칠 수 있고,
이 동작도 채팅 확인으로 기록한다. 배포 전 생성된 이름 없는 기존 `pending` 접수만 종전처럼
표시명을 먼저 확인하기 전 담당자 배정을 차단한다.

### 미진입·무효

이름을 제출한 뒤 카카오에서 메시지를 남기지 않은 것으로 확인한 건은 `미진입·무효`로
처리한다. `kakao_homepage_entries.status`는 `invalid`, 상담 상태는 `closed`가 된다.
버튼은 표시명 수정 폼 아래가 아니라 다른 상담 액션과 같은 상세 우측 상단에 둔다.
확정·배정된 상담은 이 동작으로 무효 처리할 수 없다.

## 외부 실행 게이트

대기 접수 생성 시:

- 생성: `consultation.requested`
- 미생성: 상담 접수 알림톡

채팅 확인 뒤 담당자를 배정할 때:

- 생성: `consultation.kakao_chat.confirmed`
- 생성: `consultation.assigned`
- 미생성: 담당 배정 알림톡
- 미생성: 리걸프렌즈 신건 등록

실제 전화번호와 필수 상담정보를 별도 확인하기 전까지 자리표시 전화번호를 DB나 외부
API에 보내지 않는다.

## 인증·보호

- 홈페이지 → gateway: `x-lawand-public-intake-key`
- gateway 직접 공개 호출은 전용 키 없이 거부
- 전화번호 기준 제한 대신 UUID 멱등키와 IP 원문 비저장형 회전 네트워크 키 사용
- 요청·응답 body와 고객명은 구조화 로그에 기록하지 않음

## 검증 기준

- 빈 이름·공백뿐인 이름·40자 초과·제어 문자 입력 거부와 카카오 이동 차단
- 같은 멱등키 두 번 호출 시 상담·요청 1건, 클릭 수 2
- 전화번호와 전화 지문 `NULL`
- 고객 입력 이름의 요청/상담 암호문과 `_플친` 식별자 확인
- 새 `pending` 접수의 `상담하기`에서 채팅 확인과 담당 배정이 원자적으로 완료
- 이름 없는 기존 `pending` 접수는 담당 배정 거부
- 담당 배정 outbox에 `consultation.kakao_chat.confirmed`와
  `consultation.assigned`만 추가
- 접수·배정 알림톡과 리걸프렌즈 outbox 0건
- 미진입 건은 `invalid`와 상담 `closed`, 담당 배정 0건
- 검증 데이터 전량 정리
