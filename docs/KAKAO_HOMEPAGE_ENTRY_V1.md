# 홈페이지 카카오 1:1 상담 진입 v1

## 목적

홈페이지의 카카오 상담 버튼을 누른 고객만 ERP에 자동으로 남긴다. 채팅방 진입이나
메시지 전송 성공을 알 수 없는 카카오 일반 채널 링크의 제약은 대기·확정·무효 상태로
다룬다. 직접 채널을 방문한 소수 고객은 기존처럼 수동 등록한다.

## 고객 흐름

1. 고객이 홈페이지의 카카오 CTA를 누른다.
2. 브라우저가 same-origin `POST /api/kakao-entry`를 새 탭으로 제출한다.
3. 홈페이지 서버가 gateway `POST /v1/kakao/homepage-entries`에 대기 접수를 만든다.
4. 홈페이지 서버가 `https://pf.kakao.com/_AeGxoxl/chat`으로 303 이동시킨다.

gateway 저장이 일시적으로 실패해도 카카오 이동은 계속한다. 실패 로그에는 원인 분류와
HTTP 상태만 남기고 고객 식별정보는 남기지 않는다.

## 중복 클릭

브라우저 탭의 `sessionStorage`에 UUID와 생성 시각을 저장하고 30분 동안 재사용한다.
같은 키가 다시 오면 상담과 요청을 추가하지 않고 `kakao_homepage_entries.click_count`,
`last_clicked_at`만 갱신한다. 30분이 지난 뒤의 새 행동은 새 접수로 본다.

## 데이터와 상태

- 접수 source: `homepage_kakao`
- 채널: `kakao_channel`
- 초기 상태: `pending` (`채팅 확인 대기`)
- 초기 이름: `카카오_<접수번호 뒤 8자리>_플친`
- DB 전화번호: `NULL`
- ERP 전화 표시: `010-0000-0000 · 미수집`
- 개인정보 처리 근거: `customer_initiated_channel_entry`
- 고객 발화 원문·카카오 사용자 키·가짜 전화번호: 저장하지 않음

일반 채널 링크는 고객의 카카오 식별자와 채팅방 표시명을 서버에 주지 않는다. ERP
접수번호와 카카오 채팅방 사이의 자동 연결은 불가능하므로 접수번호 뒤 8자리는 내부
동명이인 구분에만 사용한다.

## 직원 운영

### 채팅 확인

직원이 카카오 채널 관리자에서 새 메시지와 표시명을 확인한 뒤 ERP 상담 상세에 표시명을
입력한다. ERP 이름은 `표시명_<접수번호 뒤 8자리>_플친`으로 만들고
AES-256-GCM으로 암호화 저장한다. 상태는 `confirmed`가 된다. 오입력한 표시명은 확정
상태에서도 고칠 수 있고 감사로그를 남긴다.

`pending` 상태에서는 담당자 배정을 차단한다. 채팅을 실제로 찾은 뒤에만 `상담하기`를
누른다.

### 미진입·무효

버튼 클릭 뒤 카카오에서 메시지를 남기지 않은 것으로 확인한 건은 `미진입·무효`로
처리한다. `kakao_homepage_entries.status`는 `invalid`, 상담 상태는 `closed`가 된다.
확정·배정된 상담은 이 동작으로 무효 처리할 수 없다.

## 외부 실행 게이트

대기 접수 생성 시:

- 생성: `consultation.requested`
- 미생성: 상담 접수 알림톡

채팅 확인 뒤 담당자를 배정할 때:

- 생성: `consultation.assigned`
- 미생성: 담당 배정 알림톡
- 미생성: 리걸프렌즈 신건 등록

실제 전화번호와 필수 상담정보를 별도 확인하기 전까지 자리표시 전화번호를 DB나 외부
API에 보내지 않는다.

## 인증·보호

- 홈페이지 → gateway: `x-lawand-public-intake-key`
- gateway 직접 공개 호출은 전용 키 없이 거부
- 전화번호 기준 제한 대신 UUID 멱등키와 IP 원문 비저장형 회전 네트워크 키 사용
- 요청·응답 body와 고객명은 구조화 로그에 기록하지 않음

## 검증 기준

- 같은 멱등키 두 번 호출 시 상담·요청 1건, 클릭 수 2
- 전화번호와 전화 지문 `NULL`
- `pending` 상태 담당 배정 거부
- 표시명 확정 뒤 암호화 이름과 `_플친` 식별자 확인
- 담당 배정 outbox에 `consultation.assigned`만 추가
- 접수·배정 알림톡과 리걸프렌즈 outbox 0건
- 미진입 건은 `invalid`와 상담 `closed`, 담당 배정 0건
- 검증 데이터 전량 정리
