# 카카오 채널 챗봇 상담 접수 — 종료된 실험 기록

> 상태: **운영 사용 안 함.** 2026-07-30 운영 채널에서 챗봇 연결을 해제하고 기존
> 채팅방 리스트 메뉴로 복구했다. 현행 카카오 접수 기준은
> [`KAKAO_HOMEPAGE_ENTRY_V1.md`](KAKAO_HOMEPAGE_ENTRY_V1.md)를 따른다.

## 종료한 이유

챗봇 v1.0~v1.2는 첫 버튼 또는 첫 자유 메시지를 전화번호 없는 ERP 상담으로 만드는
방식이었다. 실제 운영 채널에 연결해 확인한 결과, 고객이 챗봇 상태에서 보낸 자유
메시지가 자동 읽음 처리되고 채널 상담원 화면에는 정상적으로 나타나지 않았다. 고객은
상담원이 대화를 보고 있다고 기대하지만 내부 직원은 메시지를 놓칠 수 있으므로 현재
운영 방식과 맞지 않는다고 판단했다.

운영 채널에서 다음 조치를 완료했다.

- 챗봇 `법무법인 로앤 상담` 연결 해제
- 기존 채팅방 리스트 메뉴 복구
- 일반 1:1 채팅과 평일 08시~19시 상담 운영 유지

## 보존된 비활성 코드

당시 구현한 `POST /v1/kakao/consultations`,
`kakao_consultation_contacts`, Kakao SkillPayload 계약은 저장소에 이력으로 남아 있다.
운영 채널이 스킬을 호출하지 않으므로 현행 접수 경로가 아니며, 운영 재연결·Funnel
상시화의 근거로 사용해서는 안 된다.

실험 당시의 개인정보 안전장치는 다음과 같았다.

- 카카오 사용자 키 평문과 고객 발화 원문 미저장
- 전화번호 `NULL`
- 알림톡과 리걸프렌즈 외부 실행 차단

이 안전장치는 기술적으로 검증됐지만, 상담원이 실제 메시지를 볼 수 없는 채널 운영
문제를 해결하지 못한다.

## 향후 재검토 조건

챗봇을 다시 검토하려면 최소한 다음이 먼저 충족돼야 한다.

- 봇 대화 중 상담원이 메시지를 실시간으로 볼 수 있는 공식 운영 방식
- 상담원 전환 전후의 읽음 상태·소유권·고객 안내가 명확한 시나리오
- 운영 채널과 동일한 조건의 종단 canary
- 안정적인 공개 스킬 서버, 장애 감시와 실패 시 고객 안내

현재는 홈페이지 카카오 CTA에서 ERP 대기 접수를 먼저 만들고 일반 1:1 채팅으로
이동시키는 방식이 기준이다.
