# 네이버 예약 메일 → ERP 상담 접수 v1

## 목적

네이버 예약 확정 메일을 장수명 gateway가 감지해 ERP 상담 원장에 자동 등록한다.
네이버 예약 공개 조회 API에 의존하지 않고, 공식 IMAP 메일함과 예약번호를 접수 근거로
사용한다.

## 수집 규칙

- 서버: `imap.naver.com:993`, TLS
- 메일함: `네이버예약`
- 발신자: `naverbooking_noreply@navercorp.com`
- 대상: 제목이 `새로운 예약이 확정 되었습니다.`인 예약 확정 메일
- 영업시간: 평일 08:00~19:00(Asia/Seoul), 5분 간격
- 영업시간 외와 주말: 30분 간격
- 메일은 읽음 처리하지 않는다.
- 첫 활성화 시 현재 `UIDNEXT - 1`을 기준점으로 저장해 기존 메일을 소급 접수하지 않는다.
- 이후 메일은 IMAP `UIDVALIDITY + UID`로 순차 수집하고, 실제 상담 생성은
  `business_id + booking_number` 고유키로 멱등 처리한다.

## ERP 저장과 외부 실행

확정 메일에서 예약번호, 마스킹 이름, 예약 상품, 상담 예정 시각, 인원, 옵션,
요청사항과 네이버 예약 상세 URL을 추출한다. 이름과 상담 내용은 기존 상담 원장과
동일하게 AES-256-GCM 암호화한다. 메일에 전체 이름과 전화번호가 없으므로 전화번호는
`NULL`로 저장하고 ERP에는 `010-0000-0000 · 미수집`으로 표시한다.

ERP 목록과 상세에는 `네이버 예약`, 예약 시각, `상세 확인 필요` 상태를 표시한다.
상세의 `네이버 예약 상세 열기`는 로그인된 네이버 스마트플레이스에서 전체 정보를
확인하기 위한 운영 링크다. 전화번호가 보강되기 전에는 상담을 담당자에게 배정해도
리걸프렌즈 등록과 접수·배정 알림톡 outbox를 만들지 않는다.

## 활성화

네이버 메일 설정에서 IMAP 사용을 허용한다. 2단계 인증 계정은 일반 로그인 비밀번호가
아니라 네이버 보안설정에서 발급한 애플리케이션 비밀번호를 사용한다. 비밀값은 Git에서
제외된 gateway 로컬 환경파일 또는 운영 비밀 저장소에만 둔다.

```text
LAWAND_NAVER_BOOKING_IMAP_ENABLED=true
LAWAND_NAVER_BOOKING_IMAP_USER=<네이버 아이디>
LAWAND_NAVER_BOOKING_IMAP_APP_PASSWORD=<애플리케이션 비밀번호>
LAWAND_NAVER_BOOKING_IMAP_MAILBOX=네이버예약
```

로컬 개발 환경은 애플리케이션 비밀번호 인증과 최초 UID 기준점 생성을 확인한 뒤
`LAWAND_NAVER_BOOKING_IMAP_ENABLED=true`로 활성화했다. 실제 신규 예약 canary는
기준점 생성 이후 도착한 예약 확정 메일로 검증한다.
